# ENJIN CRM（モック + Supabase DBデモ）

コミュニティ「ENJIN」の会員・イベント・起案を管理する CRM の試作です。
UI モックに加え、**Supabase（PostgreSQL）と実接続したデータベース機能**を実装しています。

---

## 🔗 ライブデモ

**https://enjincrmmock.vercel.app/**

DB機能は左メニュー下部の **「DBデモ」** から確認できます（ログインが必要）。

### デモ用ログイン

| 項目 | 値 |
|---|---|
| メールアドレス | `demo@example.com` |
| パスワード | `enjin-demo-2026` |

> ⚠️ 表示されるデータは**すべて架空のダミーデータ**です（本物の個人情報は含みません）。
> デモ用アカウントは閲覧・編集権限（editor）のみで、管理者操作はできません。

## ✅ このデモで見られること（DB実装のポイント）

左メニュー「DBデモ」画面で、以下を実際に操作できます。

1. **認証**：Supabase Auth（メール＋パスワード）でログイン。未ログインではデータを表示しない。
2. **DBからの読み込み**：会員・イベント・参加記録を Supabase から取得して表示。
3. **双方向のデータ登録**：「会員⇄イベントの参加記録」を、
   - **① イベント側から**（このイベントに、この会員を追加）
   - **② 会員側から**（この会員を、このイベントに追加）

   の **どちらからでも登録**できます。
4. **単一テーブルで一元管理**：①②どちらで追加しても、保存先は同じ中間テーブル
   `event_participants` の1行。だから追加した記録は一覧に即反映され、
   **リロードしても残り**、両方向から同じデータが見えます。
   → 多対多（会員 ⇄ イベント）を**リレーショナルに双方向管理**している実例です。

## 🛠 使用技術

| レイヤ | 技術 |
|---|---|
| フロント | React（CDN + Babel standalone のシンプル構成） |
| DB / 認証 | **Supabase**（PostgreSQL / Auth / Row Level Security） |
| ホスティング | Vercel |

### セキュリティ（個人情報を扱う前提の設計）

- **RLS（行レベルセキュリティ）を全テーブルで有効化**。ログイン済みユーザーのみ読み書き可。
- フロントに置く `anon` キーは公開前提の鍵で、アクセス制御は RLS が DB 側で担保。
- 新規サインアップは無効化し、利用者は**招待制**で発行。
